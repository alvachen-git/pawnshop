# 玩家文案规范

依据：负责人于2026-09-04试玩通过M5后提出的文案修订要求。本规范适用于后续玩家可见的对白、旁白、选项、物品、警告、结果和界面文字。写作对象是正在当铺里做决定的玩家。

## 写作原则

1. **从玩家能感知的事物落笔。** 镜中人慢半拍、香灰倒伏、命灯贴向镜面，比“风险升级”“状态异常”更能交代危险。采用简明白话与适量时代用语，不堆砌故作古奥的辞藻。
2. **危险要预警，结果不预报。** 在选择前提供可识别的禁忌或异常，例如“别应声，也别看它的眼睛”。不写“选择后永久死亡”“读档无法复活”，也不提前保证某一选项必定保命、必定留下什么状态。隐晦来自结果未知，而不是把必要规则藏起来。
3. **选项写行动、说话或态度。** 如“低头退开，将红布覆上”“抬眼看向镜中人”。不加“保命”“致命”“明知死亡”“正确”“收益+”之类的答案标签，不替玩家声明他已经知道尚未发生的结果。
4. **关键操作保持清楚。** 可以明确“关门前覆红、落闩后莫揭”；时钟、报价、费用、处理分钟等决策依据仍直接显示。不要把经营数字都改成谜语，也不要通过文案暗改可执行动作或成本。
5. **剧情与软件操作分开。** 镜中危机、死亡旁白、人物对白中不出现存档、检查点、配置、未实现、占位、Milestone等制作术语，不追加通用的“已保存”信息。新游戏、读取存档、退出等专门菜单和必要的确认提示可以直白易懂；写盘失败、版本不兼容等真实错误必须如实提示，不能用怪谈暗语掩盖。
6. **结果发生后再描述痕迹。** 生还可写“红布下再无声息，影子却迟迟没有归位”；死亡可写灯冷、账册翻页。《绝当录》交代死因及遗留资产，但不以开发日志或评判口吻训斥玩家“明知故犯”。
7. **不泄露调度与隐藏信息。** 正文不预报“第三夜固定来镜”“此选项解锁某标记”“此后每夜风险增加”。角色可以给有来源的消息；信息的确定性应符合其身份与认知。
8. **少写，留出停顿。** 每段围绕一个动作或异象，避免解释同一后果两遍。危机的必要警告与选择尽量一屏可见，操作按钮不被冗长旁白挤走。

## 对照示例

| 避免 | 采用 |
| --- | --- |
| 永久结束本轮经营，读档也无法复活 | 命灯的火苗细成一线，朝镜面伏去。耳边有人低声道：“别看它的眼睛。” |
| 明知会永久死亡，仍直视镜中人 | 抬眼看向镜中人 |
| 低头退开，用红布裹镜（保命） | 低头退开，将红布覆上 |
| 夜间结算不再消耗营业时间；检查点已保存 | 从危机正文中删去；需要说明操作规则时，放在独立帮助或功能界面 |
| 本轮已终止，死因已记录 | 灯芯烧尽了。柜上的账册无风翻开，停在一张空白页上。 |
| 第三夜可能有人带来一面铜镜 | 柜门掩着，暂时没有什么动静。 |

## 交付前自查

- 玩家是否知道眼前有什么异常、自己能采取什么行动？危险是否在选择前已有线索？
- 选项是否只表达行动，是否偷塞了结局、隐藏状态或最佳答案？
- 剧情里是否混入程序、存档、开发阶段等出戏表述？功能菜单是否仍然清楚？
- 文字是否与实际规则吻合，是否把“可能”误写成“必定”，或宣称没有实现的功能？
- 是否检查了上下文一起显示的提示，而不只修改单条字符串？是否看过真实游戏画面？
- 仅改文案时，保留稳定ID、行动成本、效果、存档结构和玩家历史。历史记录中的文字快照不作为判断生死的依据；用规则ID、选择历史和资产状态校验。

玩法规格、QA步骤和开发文档可以准确写明死亡与保存机制；这些解释不应直接复制进玩家剧情。后续新增内容按本规范复核，不需要把工程验收条件逐句展示给玩家。

## 每日息费与铜镜窥探补充 · 2026-09-04

- **经营承诺说清楚。** 本金、利息、铺面开支、欠款金额和到期夜次是决策依据，可以直接展示。例如“第1夜短款3银元，第2夜夜末须补齐”，不能只写“债主快来了”而隐去期限。
- **未知后果留在情境中。** 铜镜可以先让玩家看见值得追查的旧当票，再通过回头的倒影、缩短的灯火提醒危险；选项只写“收回视线”“看清那张旧当票”。
- **提示符合当前持有状态。** 已卖出的镜子不能还被写成摆在柜上。追看留下的影子跟随玩家，危机写身后的影子；覆镜动作只用于仍在铺里的铜镜。
- **异象和选项一起审。** 关键选择时减少存放说明、历史账册等附带文字，让必要警告和两条行动在小分辨率下同时可读；危机切换后从正文开头显示。
- **失败发生后交代账目。** 《破铺录》可直接写到期短款与遗留资产；正文写封条、催账与关铺，不把存档、终止阶段或程序判定复制成旁白。
