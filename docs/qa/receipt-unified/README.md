# 统一成交凭据 · 发布验证

本修复基于 main 的 `60736d6`，保留已经上线的独立议价面板、持续顾客回话、历史凭据复查、夜市规则和灯光。仅发布本次成交凭据改动；未包含另一工作区中的寝屋或铜镜换物功能。

## 原因与修复

- 原 `_show_receipt()` 将普通成功交易导向底部反馈，只有带 `tutorial` 配置的收购弹凭据。这是成功交易有时没有凭据的直接原因。现在所有真实成交均展示同一张可主动确认的凭据。
- `tutorial` 也用于第四夜搬家客等来访的议价容错，并不代表首夜教学。移除这一错误判定及视图里硬编码的首夜妇人对白；即时凭据使用本次来客的实际完成对白。
- 所有成功凭据进入时显示红印、播放盖章声：付款“付讫”、收款“收讫”。点一次“收好凭据”继续；未成交的离场通知沿用原有持续回话，不盖成交印。
- 首单的“第一笔账”提示合并到凭据，仍经原事件入口写入一次历史与剧情标记。没有改动存档格式、报价、耗时或钱货结算。
- 已成交凭据在封铺刷新时继续保留；旧凭据仍可从账本复查。批量销售的历史买家、金额和续当的历史期限保留 main 现有的按交易重建逻辑。
- 补齐付费行家复核的费用凭据。重复报价、拒价或重复复核不新增成功凭据。
- 成交凭据确认后恢复底部回话；重复通知按本局和交易 ID 去重，恢复存档与返回标题清除旧显示。

## 验证方式

使用 Godot 4.6.1，在独立发布工作区及独立测试存档目录执行。相关源代码没有在测试后被其他本地任务修改。

- `receipt_consistency_ui.gd`：首单一次确认、第二至第七夜逐客成交、第四夜紫砂小壶、封铺刷新、付费复核与重复提交；1280×720 和 1600×900。
- `receipt_ui_smoke.gd`：收购、卖货、活当、铜镜后续提示、账本历史批量凭据复查；两种尺寸。
- `customer_reply_ui.gd`：成功凭据与原客回话衔接、拒价、超时和送客；两种尺寸。
- `trade_feedback_lifecycle_ui.gd`、`opening_ui_smoke.gd`：存档恢复、标题切换及首单剧情。
- `bargain_modal_production_ui.gd`、`night_market_ui.gd`：保留正式议价界面与夜市特殊规则。
- `run_all.gd`、`run_market.gd`、`run_opening.gd`、`run_early_redemption.gd`、`run_goods_expertise.gd`、`run_negotiation_reactions.gd`：相关逻辑回归。
- `git diff --check`：改动格式检查。

运行结果见 [验证摘要](validation.txt)。截图来自该发布分支，使用隔离来客测试场景，资金不代表玩家存档。
