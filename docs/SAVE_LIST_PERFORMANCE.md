# 保存与读取列表停顿 · 2026-09-15

问题：`SaveLibrary.entries()` 为生成每一行摘要调用完整解码；再次打开、切换列表或刷新时重新做同样的工作。首次解码还会加载全部历史内容。v23的解码包含操作历史重放，列表中的多个存档会把这些耗时累加到主线程上。

修复：只加载与存档版本相符的内容；对已校验过的列表摘要作进程内缓存。缓存键包含完整条目内容摘要及旧档/扩展校验模式，最多64项，不使用文件时间或存档位名称判断是否未变动。缓存只保存显示文字、版本和有效性结果，不复用可变运行状态。正式保存和读取始终完整校验，原有原子写入、回读及错误保护保持不变。

本机同一隔离测试库：六个相同十夜末进度的手动存档，用于测量重复解码；不代表所有真实存档组合的耗时。

| 操作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次列出 | 3101 ms | 594 ms |
| 再次列出 | 2167 ms | 122 ms |
| 实际读取单档 | 405 ms | 566 ms |
| 实际写入单档 | 622 ms | 587 ms |

本次改善的是重复列表校验。首次遇到多个不同进度、旧版本的存档仍需各自校验；实际读写仍在主线程上执行，可能有短暂停顿，未宣称异步或零卡顿。随后对v23连续检查点增加了已验证历史前缀复用，见[开铺与回房响应优化](CHECKPOINT_PERFORMANCE.md)；上表是增加该优化之前的列表专项结果。

验证：`tests/save_list_cache.gd` 在主目录及v23各11项通过，覆盖首次校验、重复缓存、返回值隔离、外部修改后失效、篡改拒绝、写盘失败保留原文件。`tests/manual_save_tests.gd` 1163项通过。`git diff --check`通过。已同步独立v23试玩目录，未推送。
