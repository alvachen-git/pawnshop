## 玩家流程

- 第二夜起，主动查看寝屋衣柜，发现旧衣下的小号夹袄；不说明主人、年代或死亡。
- 第五夜起，打开书桌旧信，选择“看看夹纸”，看到风车画与试折痕。旧信、照片用途保留。
- 两处均可完全错过，首次发现保存到事件历史，复看不耗时、不收费、不重复记入。没有弹出提醒，不影响主线登场。
- 第七夜核票、息费结算和铺内危机处理后，阿七在柜台边请掌柜看看风车。先接过或先问名字；问名后可以帮忙或婉拒。帮助只需理开纸翼，无小游戏或失败判定。
- 已看过夹纸的人在修好后可追问画纸；回答仅谈画法与折法。没有看过的人不会出现该选项，仍能自然完成初见。
- 阿七带着风车离开。掌柜翻旧《阴账》，看见“尚欠七账”，再选择查看抽屉或收好账本。查看所得半张旧铺草图可从末夜寝屋书桌复查；略过不补发。
- 完成后正常回房、就寝和结局。不生成第八夜，不强制通关。现有命灯或铜镜后果继续有效，墙镜没有新增剧情异象。

帮助、婉拒均不增减钱、库存、债务或关系值。“尚欠七账”是文字线索，不生成七笔应付金额。本批不揭晓阿七身份、与顾敬堂的关系或留魂契；不新增婚讯转折、任务背包、好感面板或第二套剧情存储。

## 内容与阶段

入口为 `scenes/start.tscn` → `data/aqi_manifest.json` → `aqi_seven`，`save_version=22 / content_version=22`。独立自动位 `auto/aqi_seven`，路径登记 `user://aqi_seven/autosave_v22.json`。v21及更早内容数据保持原样，按原运行继续；从旧局返回默认标题再新开进入v22。

数据位于 [events.json](../data/aqi/events.json)。流程为：

```text
aq_arrival → aq_inspect → aq_repaired → [aq_paper_reply] → aq_departure
        └→ aq_name → 帮忙同上 / aq_declined ────────────────┘
aq_departure → aq_ledger → aq_drawer → 查看 aq_floorplan / 略过 → 回房
```

核心引用标记：`aq_coat_seen`、`aq_paper_seen`、`aq_helped`、`aq_declined`、`aq_paper_asked`、`aq_plan_seen`、`aq_chapter_done`。其他 `aq_` 标记用于已有事件引擎的阶段编排。历史记录稳定事件ID、选择ID、夜次、阶段和分钟；已知标记由历史回放重建。

`EventDomainValidator` 允许封铺后的 `shop_resolution` 零耗时事件。`EventSaveCodec` 以开铺前、营业、关铺处理、铺内收尾、寝屋、就寝排序；铺内事件必须存在封铺记录，危机未决时不能提交完成历史。`RoomSaveCodec` 回放上楼动作时检查铺内待办，拒绝删除阿七历史与标记后伪装已进房间的存档。

第七夜封铺时先登记待办；`RunSession.event_model` 在危机期间隐藏其正文、展示与选项，风险接口可优先处理危机。死亡清空待办；存活继续同一事件链。上楼接口要求事件已完成。

`RunSession.observe_room` 是观察应用入口：核验可见性，使用已有事件调查与选择机制，首次发现原子保存，写盘失败回滚并提示重试。Presenter提供可见内容、已知状态，View只显示并发出观察意图。普通铜镜调查面板不混入这些寝屋观察条目。

2026-09-14按负责人要求改为原柜台内呈现：`CounterPresenter`提供事件，`CounterView`复用普通客人的人物位置、货物位置和点击热点，`CounterStoryView`在柜台右侧显示纸质对白与选择。阿七不进入普通来客队列，不创建交易与离场通知；`NarrativeScene`仅负责原有开场等内容。收起按钮或Esc关闭对白，点击阿七或纸风车继续；菜单、账本可照常使用，操作不会推进剧情。剧情完成后显示原夜末回房入口。事件ID、选择历史、存档版本及风险规则不变，已有v22中途存档直接使用新呈现。
