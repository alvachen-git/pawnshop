# 主菜单进入游戏性能

2026-09-16，本次修改应用于启动入口 `scenes/start.tscn`。首次测试为本地 v22；发布前移植到线上 main `221c1321e1f3db362970ab53750deb5f037474e3`（v24 十夜入口）并重新验证。

## 调整

- 启动时已经生成第一夜；第一次点击新游戏直接进入这局，避免重新生成随机来客编排。返回标题后再次开局仍重新生成，读档后亦如此。
- 柜台在不透明标题画面后预绘制一帧，提前准备纹理与字体。随后恢复隐藏；整个预热期间游戏处理保持禁用，不推进状态、不写档。无图形测试跳过预绘制。
- 存档库复用启动时已经通过校验的当前版本内容，避免首次打开列表时重复加载。指定调试种子时不复用被修改过的运行定义；其他版本仍分别加载、校验。
- 成功读档发布状态时，不再重建马上关闭的存档列表。失败仍保留列表与错误提示。
- 完整存档校验、失败保护、存档格式均保留。

## 测量

Windows / Godot 4.6.1 / Compatibility / RTX 3060 Laptop，实际图形窗口，隔离 APPDATA。
本地 v22，六个第一夜手动存档；同一次进程首次点击到 `frame_post_draw`。以下为本机单轮基线和回归样本，非所有硬件或复杂长局的保证。

| --- | ---: | ---: |
| 新游戏点击回调 | 69.8 ms | 0.8 ms |
| 新游戏到首帧 | 249.4 ms | 11.7 ms |
| 打开读取列表回调 | 134.0 ms | 38.5 ms |

线上 v24 发布目录复测：新游戏回调 1.0 ms、首帧 9.0 ms；读取列表回调 67.0 ms、首帧 77.5 ms；选择存档后读取回调 112.8 ms。版本内容不同，不与 v22 数据直接计算提升比例。

首次绘制成本移到标题首次出现时完成一次，不在点击后才发生。历史复杂存档仍需完整验证，耗时取决于内容；没有使用跳过校验的捷径。
