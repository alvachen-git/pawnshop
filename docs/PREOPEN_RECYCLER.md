## 玩家流程

1. 第一夜正常收货，营业页不显示卖货入口。库存只保留铺中货物与出柜记录。
2. 第二夜开铺前，完成眼前的登门对话后，从营业页选择“卖货 · 杂货回收商”。
3. 点击货盘选货，确认交货才扣1行动点，一次可卖多件；与每夜2点准备／鉴定额度共用。收好成交凭据后返回营业页，仍处于开铺前，不推进营业时间。
4. 看价、取消和收起免费。同日再打开保留有效选择；换夜或读档清空草稿。
5. 开铺后不能向杂货回收商交货。行动点耗尽仍可查看价格。陆掌眼继续由右下角信件进入。

## 定价与渠道

- 按本局种子、夜次和物品定义ID使用独立随机序列生成70～100的整数比例；同种货同日同价，次日可能恰好同价。
- 价格为 `max(1, floor(base_value * rate / 100))`，逐件取整再汇总。例如基础价25、比例87%，实收21银元。
- 品相、真假、损坏、来源和鉴定均不改变杂货报价，不给成套奖励；不泄露隐藏实物估值。
- 只收普通渠道、自有且没有未处理危险限制的货物；在当、已售和特殊鬼货不可直接回收。
- 瓷器收藏客、街口银楼暂隐藏并拒绝直接交易命令。文房约定在调查消息后或第六夜展示，交货条件沿用旧约定。夜半收镜客仅在持有未解脱铜镜时展示。
- 文房、收镜和陆掌眼保留原有价格、窗口、20分钟往返及剧情条件。

## 实现约束

`RecyclerPolicy` 集中管理版本、定价和渠道。`CommerceService.quote` 增加可选当前营业上下文，旧调用格式仍有效；批量结算及新页面显式传入该上下文。
批次记录 `action_points: 1`，共享行动点根据当夜已验证交易历史计算，不另存可篡改余额。
`RunSession.sell_batch` 与旧 `commerce_command("sell", ...)` 都原子保存，失败还原货物、资金、时间、行动点和操作历史。
存档重放计算实际价格与批次消耗，不信任票面报价或UI草稿。
