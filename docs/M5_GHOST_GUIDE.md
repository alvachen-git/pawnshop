# M5 鬼货规则与边界

生产入口为`data/content_manifest.json`，content_version=6/default_run_id=p0_m5。M4内容不删除，测试通过独立`tests/fixtures/m4_manifest.json`继续覆盖原388条断言。

## 配置入口

- `data/ghost_rules/rules_m5.json`：GhostRuleDTO → 只读GhostRuleDefinition。字段为id、mechanic、warning、crisis、death_cause、cover_minutes、uncover_minutes。
- `data/items/items_m5.json`：铜镜是普通物品定义结构的`type=ghost`，使用`ghost_rule_id`引用规则；原鉴定证据/前置工具、议价和现金入口继续生效。
- `data/runs/p0_m5.json`：`ghost_rule_ids`启用规则，第三夜固定来访槽带镜。所有普通货仍在三夜编排中出现。
- `data/buyers/buyers_m5.json`：夜半收镜客，00:00–02:00、每夜一件、1.5倍率，使用既有买家交易系统。

目前机制只支持`cover_before_close`与每轮一次固定夜次鬼货来访。未知机制、丢失引用、重复规则、不匹配的耗时步长、多鬼货/重复鬼货来访会被拒绝。该约束是M5范围门禁；下一机制应新增明确的领域策略及测试，不执行配置中的任意脚本。

## 时间与后果

| 情况 | 结算结果 |
| --- | --- |
| 关门时未留鬼货 | peaceful |
| 关门前盖好，关门后保持遮盖 | mirror_safe |
| 未盖关门，随后补盖；或关门后揭开又补盖 | mirror_scar |
| 封铺时仍未遮盖 | mirror_pending，阻止推进，给明确危机警告 |
| 警告后低头退开、裹镜 | mirror_survived，留下缠祟 |
| 警告后明确选择直视 | mirror_death，永久终止本轮 |

规则期限按GDD铜镜描述采用“关门前”。关门后仍可补救，但不撤销已触发的异常。营业时揭开后重新盖好，不虚构关门违规。处理动作是原子耗时动作；02:50开始盖10分钟，会先完成遮盖，再于03:00自动封铺。02:55无法透支执行10分钟处理。

红布随镜提供且可复用，避免P0变成消耗品商店系统。夜间应对发生在日结阶段，不再消耗营业时间；无需抽象行动点，第一次数值未知也不直接杀人。命灯/财神香用可读文字呈现，没有公开血条、邪气数值或随机死亡。

`risk_history`为权威处理日志；覆盖状态、关门违规与环境后果从日志和日结推导。持久缠祟取自历史结果，所以以后正确处理不会抹除它。当前缠祟体现为持续叙事/灯火状态，不冒充后续尚未实现的复杂索命系统。

## 模块职责

- RiskManager：处理可用性、分钟成本、关门快照、结果、警告响应和死亡记录。RunSession负责与日循环、交易、事件和保存的调用顺序。
- RiskReadModels：构造面板文字、可用意图与环境反馈，不改变权威状态。
- RiskPanel/RiskPresenter：展示和发送意图；入库、早关异常、危机/死亡时路由到对应面板。
- RiskSaveCodec：历史时序、持有期、关门快照、动作成本、应对前置、日结结果与死亡标识交叉校验。
- SaveManager：将当前检查点与death_archive一起临时写入、回读验证、原子替换。不存在第二个需要同步提交的死亡文件。

## 保存契约

save_version=5，增加run_token、risk_history、risk_pending、death_archive。启用鬼货的每次新运行有独立随机标识；该标识只用于运行身份，不参与客流/事件随机。老版本检查点不迁移。

阶段`day_summary`可带待处理危机；解决后原子更新结果。`dead`是终止检查点。同run_token已有死亡记录时不能保存/恢复为存活。重开更换token，保留历史记录，不返回死去的同一轮经营。

《绝当录》保存死因、夜次、关键鬼货名/实例/规则、遗银、现货成本、在当本金。现货成本不当作现金或可清算财富；正式未清阴账摘要需等阴账系统落地。普通夜内退出回到上个检查点；不提供对外部手工替换整个文件的防作弊保证。

每次结算/夜间响应写盘失败时，RunSession深拷贝回滚全部状态；重新点击只提交一次。存档中的绝当录结构损坏或同token内容冲突会拒绝覆盖。仅支持单窗口，不支持多实例并发写入。
