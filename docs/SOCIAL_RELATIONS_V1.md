## 已接入的规则

### 商誉与来客

隐藏整数 −100～100，初始 0。只结算普通客人的收购和活当；军方货源、剧情客、阴客、赎回、出售不套用。

比较基准为最初开价减去通过议价认可的有效瑕疵折价，最低 1。普通压价、急用钱让价、贬低物品均不改变基准；同一条证据不能重复使用。活当按现有贷款比例换算。

| 接待最终结果 | 变化 |
| --- | ---: |
| 实际成交价达到基准 120% | +2 |
| 实际成交价不超过基准 80% | −2 |
| 中间价格成交 | 0 |
| 最后有效报价不超过基准 60%，被拒后谈崩或主动结束 | −1 |
| 没有报价的正常拒收、等候超时、关铺 | 0 |

报价失败但仍在谈判时不结算，未支付的高报价不加分。每次接待只结算一次；每夜价格带来的正向、负向变化分别最多 6 点。因检查而耗尽耐心，不把先前报价当作本次谈崩的直接原因。

次夜开铺前锁定普通散客调整：≤−50 减 2；−49～−20 减 1；−19～19 不变；20～49 加 1；≥50 加 2。只能删除可替换的普通散客，至少保留 2 位；剧情、熟客关键回访、赎当和已约定来客保留。玩家招揽和设施买家另算。当夜交易不会刷新当夜来客。

玩家通过署名离店评价、街坊口信和新增客人的介绍理解变化；界面不显示分数或精确门槛。付款厚道时不会继续沿用与实际付款相矛盾的统一不满评价。

### 孙大元与驻军

隐藏整数 −100～100，初始 0，第二夜介绍。与商誉独立。

| 关系 | 停业 / 保护费 / 货源机会 | 费用或待遇 |
| --- | --- | --- |
| −100～−80 | 35% / 45% / 0 | 保护费 35，撤令 50 |
| −79～−50 | 20% / 35% / 0 | 保护费 25，撤令 35 |
| −49～−20 | 0 / 35% / 0 | 保护费 15 |
| −19～19 | 0 / 0 / 0 | 基础采购 |
| 20～49 | 0 / 0 / 25% | 四份基础货源 |
| 50～79 | 0 / 0 / 40% | 追加两份优质货源、重要采购 |
| 80～100 | 0 / 0 / 55% | 两件不同货物择一、人情采购 |

概率只在符合条件且不处于冷却的开铺前抽取，三个主动事件互斥。首次跌至 −20 先留下警告，下一次符合安排条件时先收一次保护费；经过收费和停业威胁后才有停业令。每次主动事件之后两个完整夜次不再投放。

保护费支付 +2，拒绝 −8；拒绝后当夜仍可营业，没有永久欠款。停业令只约束当夜，可支付手续费用、消耗一次说情机会或守铺停业。撤令不加关系，送礼不能移除已经送达的命令。停业令处置后四个完整夜次内不再出现。

停业时停止新来客、主动出货和军方新货源交易，仍可接原当户赎回和进行允许的铺内活动；息费照付，停业本身不扣商誉。已接受采购单和受阻预约顺延一夜；不可延期的主线会面与特定剧情来客所在夜不投放停业。

送礼花 20 银元、占一次开铺前准备，+8，隔两个完整夜次后可再次送。基础采购完成 +10，重要和人情采购完成 +15，均提供一次不叠加的说情机会。接受后取消 −10，到期未履行 −20；未接受前婉拒为 0。一次只有一张采购单，结束后空出两个完整夜次。关系恶劣时仍可送礼、接基础修复采购。

### 货源、鉴定与追索

基础四份：怀表、钢笔、银簪、青花碗；高关系追加紫砂壶、绣片。四份来源清楚、两份有权属疑点，复用已有物品和带货人立绘。真相固定，抽选与种子绑定，不因查看或读取改变。高关系一次最多买一件。

先约带货人，开铺后在原柜台鉴定和议价付款；可以在购买前花 2 银元、10 分钟核查专属来源线索。不买不扣关系。军方货物没有保底转售价，正常寻找销路。

疑点货购买两夜后，旧主携字据上门。当前首批追索明确发生在街坊见证下：

- 协调退还仍在铺中的原物，退回原收货款：商誉 +2、军方 −4。
- 按原收货款一半向旧主补偿、签订和解：商誉 +2，军方不变，货物去向不变。
- 关系足够或有人情时请军方出面：商誉 −4、军方 +4；持有人情时消耗它。
- 无法立即办理时可推迟一夜；仍不处理则旧主公开投诉，商誉 −4，结束此事，避免资金耗尽导致卡住开铺。

这些是事件各自的明确结果，不是两项数值自动联动的通用规则。

## 技术与内容边界

主要配置：`.artifacts/social-relations/data/social_relations/rules.json`，包含价格阈值、商誉单夜上限、关系档位概率、军方费用、送礼收益、冷却、货源真相和采购单。

独立社会状态记录分数、原因、当夜客流、事件、说情机会、采购、货源、追索及延期。交易结束、开铺编排、军方操作分别调用规则；界面不直接修改分数。军方费用进入现有账目，采购交货和退还原物走真实库存与收款。用户操作纳入原来的动作重放存档，验证失败不载入；写盘失败撤回现金、次数、关系和动作记录。

首版没有新增武器、第二个军阀势力、外交战争、全局售价/耐心奖励或自动赠送的军货。正式十夜内靠送礼通常只能提升数次；高关系内容可通过专项场景查看。没有为了展示全档位而加快正式版增长速度。

## 验证与首轮经济观察

运行命令与结果见同目录 `SOCIAL_RELATIONS_VALIDATION.md`。已验证规则边界、成交和失败终局、防重复、保存失败回滚、客流保护、停业三条路径、采购修复、货源鉴定付款、追索处理、十夜流程、旧版经营和铜镜剧情；实际界面检查覆盖 1280×720 与 1600×900。

**数值仍是首轮试玩默认值，不能据此宣称经济平衡已定稿。** 实际十夜自动经营对比中，机械地收下所有便宜货、对所有客人高价付款都容易耗尽现金；“厚待客人”在这个脚本里尚未自然积累到客流加成档。高低商誉的客流效果由独立边界场景验证。应进一步真人测试“挑货、验瑕疵、保留周转金”组合下的体验，再决定是否调整赠礼成本、来客收益或声誉增长速度；本轮没有擅自修改已确认的默认值。
