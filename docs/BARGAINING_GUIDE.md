# 议价说辞与一次性试探

分支 `codex/bargaining-feedback` 增加议价说辞与一次性试探。初版经本地测试确认后，负责人批准推送并合入 main；整合基线为 `eb8cdd9`，包含已合并的房间、成交页、原主赎当与逾期处置。本轮仅交付源码，不制作试玩包。

## 玩家体验

- 原来的“据此压价：……”改为议价说辞，下面完整显示对应证据。青花碗具有逐条说辞与反驳；其他未配置专用说辞的证据使用“拿这条线索试探价格”。不隐藏无效理由，不用颜色预告效果。
- 已谈过的证据仍列出并禁用，同组瑕疵只折价一次。所有可执行的证据议价标出耗时和轮次；证据、人物态度及反馈可滚动阅读。
- 普通收购、活当共用一次“这东西没你说的那么值钱，再让些。”，每次接待消耗5分钟、一轮。不是成交，不产生流水、库存或成功页，也不改变证据估值。
- 旧城住户、富户管事普通让3银元，已配置的急迫处境让5银元；夜市货郎不让价、不额外掉耐心；旧书铺先生不让价并扣2点耐心。性格固定，处境使用原来的来访安排，不新增随机数。
- 让步同时影响要价和收购底价，最低1银元；活当沿用原有比例。轮次或耐心耗尽后仍按原规则离场，完成时已离场的行动没有议价效果。
- 人物底色通过对白和动作提示，界面不展示性格类型、隐藏底价、真值或成功率。美术继续使用现有草图。

## 内容与接口

`ClueDefinition` 增加可选 `bargain_line` 和 `bargain_response`。客户增加可选 `belittle` 配置，包含 `reaction`、`minutes`、`ordinary_discount`、`urgent_discount`、`patience_cost`、`cue`、`response`；缺少配置的历史客户不显示新动作。Schema 校验类型、枚举、范围及耗时步长。

`belittle` 是独立柜台命令，复用阶段、来客、时间及议价资格检查。会话的 `belittle_used` 保证收购与活当不能重复试探，不占用物品证据 ID。展示文案与证据效果独立，不通过文本判断规则。

交易面板为按钮附带稳定的行动、证据标识。UI 回归按这些标识找到控件，然后发送真实视口鼠标输入；不再用可能相同的备用文案区分证据。

## 存档与集成

沿用 main 的 save v9/content v9 及既有检查点，不新增夜内自动保存。有情境来访继续使用 `scenario_history`；配置了新议价机制的普通来访使用可选 `bargaining_history` 记录柜台行动。两类历史分别用同一个柜台规则重放，每条新试探记录保存实际使用状态、要价、轮次、耐心及原有行动时刻。JSON 数值在比较前规范化，不能靠重复记录再次获得让步。

旧档缺少普通议价历史时视为没有新记录，不重算旧交易；记录存在时进行重放验证。原有铜镜外部取证从其独立历史恢复，并继续经过铜镜校验。写盘失败与重试保留原有原子保存和完整状态回滚。

已整合 main 的活当回访流程，保留回访优先阻塞、普通来客顺延到店和旧 v7/v8 存档兼容逻辑。两类议价历史均按真实回访延迟重放；新试探仅属于普通货物议价，不向回访添加该按钮。联合测试覆盖回访拒绝试探、赎回后新接待可试探及跨夜历史恢复。
