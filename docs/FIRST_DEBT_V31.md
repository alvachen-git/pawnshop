# 龙镯追查 · v31

## 动机与事实

沿用v29正史：陈阿福为妻子治病，将母亲留下的一对金镯活当七夜。顾敬堂第五夜提前售出，后又打点驻军阻止追讨；陈家原票有效，不是改票，也不归咎陈阿福记错期限。陈小满保存祖父遗愿与原票，先疑认、后核实。

新段落放在正式告知违约事实之后。玩家看过两联票、出货凭据及工记/修补，陈小满说：“祖父留下的镯匣有两个窝。如今凤的找着了，龙的还不知道在哪里。他一直盼着能把这一对找回来。”

玩家答应或暂缓；另保留商量300银元赔偿入口，不强迫先找龙镯。凤镯已出售时承认其实际下落。答应不占时间，准备行动才消耗共享次数。陈小满不替玩家提供龙镯确切所在。答应或暂缓后，后续再谈必须在开铺前“约陈小满来谈”，消耗一次共享准备，不另收费。开铺后空柜接待，不占普通客位；一次约见不跨日循环，错过需重约，军方停业免费顺延。归还、赔偿、暂缓、拒绝及后续回应结束均离场；陈家原票首次送来及认物前流程不变。

陆掌眼经正常旧货渠道取得龙镯，只是当前持有人。回信先说符合描述，柜前验看才能确认工记与纹样成对。150/200是固定转让价；不混入他平时收购货物的报价。

## 状态与提交

- `DragonSearch` 是应用层规则和只读投影，状态来自原 `preparation_history`、`event_history`、库存与商誉。
- `fd_search_motive` 记录答应/暂缓。`dragon_search`准备记录委托；`ds_search_message` 通过现有`shop_resolution`事件记录收信。
- `chen_invite`记录陈小满的后续预约，沿用准备历史；`fd_settle` / `fd_followup` / `fd_meeting_end`标明当次谈话结束。
- v31新动作日志带`chen_visits: 1`来访规则修订号。旧v31日志按原规则逐条回放，恢复到当前界面后采用预约规则；第一次新动作后不得降级回旧规则。旧v28/v29不变，不删除或重写玩家历史。
- `dragon_invite`记录预约。当前有效夜由原预约夜和主线停业夜历史推导。无第二份预约/任务存储。
- `fd_dragon_quote` 的`fair/dear`选择历史记录锁价；由应用层按当前商誉核验，不能伪造另一价格。`fd_dragon_deal`购买或暂缓结束当次会面。
- 所有命令进入原动作日志。失败回滚现金、物品、准备次数、事件、待办；重复请求无额外扣款或发物。首次报价也原子保存。
- 陆掌眼使用独立柜台会面投影，等待当前交易/赎当/会面/危机结束；普通接待算法和主线预约仍运行。UI结果页保留人物到回应读完，随后关闭，不直接弹出另一人的话。
- 身份确认、免费阅读及报价不推进时钟，购买5分钟。原有托话、核实、说明事实、赔偿耗时保留。
