## 上一版流程（已由客户回复方案替代）

普通成交：客人与原物保留在柜台 → 交割、收讫或当票印记 → 实际现银变化 → 自动继续接待。总演出时长 0.72 秒；动画与声音复用现有资源，不增加游戏时间或行动次数。钱款仍由真实流水一次性入账，状态栏在演出的钱款阶段同步显示结果。

| 规划项 | 当前行为 |
| --- | --- |
| 来客入场 | 人物、物品短暂淡入，物品轻移；显示只卖、只当或卖当皆可。 |
| 检查、追问 | 鉴定页标出本次发现；对话页标出最近答复，物证与未证实口供分开。使用过的议价依据沿用明确标记，不提前显示隐藏信息。 |
| 报价不成 | 未成交保留当前接待；显示实际回应、要价与客人态度，不展示剩余轮次；错误施压与拒价沿用不同反馈。 |
| 普通成交 | 收购、活当、赎回、续当、出售自动演出，输入暂时阻断，无额外确认。批量出售只演出一次汇总。 |
| 货物去向 | 收购收入现货；活当留铺保管并显示到期夜次；赎回原物交还；出售交货收款。 |
| 拒收、离场 | 原客携物离去，不播放收款或收货章。等候客离场只留通知，不打断仍在进行的接待。 |
| 凭据复查 | 操作区最近结果条目可收起；主动点开详情，或由账本流水打开单笔／批次凭据。关闭复查返回原页面，金额保持历史快照。 |
| 必要剧情 | 开场首单仍手动盖章；铜镜规矩、剧情选择及夜间危机继续保留，不由自动演出跳过。 |
| 顺序、取消 | 完成原客结果才更新柜台；重复刷新不重播；读档、新局、返回标题、切换面板取消未完成演出。跨夜旧离场通知不盖住新夜的内容。 |
| 活当意愿与条款 | 不能活当时说明原因，不展示假当约；只当客明确不接受收购。现金、时间不足或议价已结束等临时限制单独说明，但不展示剩余轮数；输入超过现银时禁止提交并解释原因。 |

## 边界与兼容

- `RunSession.operation_completed` 提供操作前后公开快照和结构化离场原因；`transaction_completed` 只由新增交易流水产生，不能用 `ok` 或对白猜成交。
- 新增表现状态不写入存档；不改价格、底价、耐心、耗时、资格、来客编排、行情或人物关系。读取旧档继续使用该档原有规则，不需要为此次表现修改废弃旧存档。
- 历史批次按流水对应的批次和买家重建，不误用最后一批交易。旧开票凭据保留原到期日，续当凭据显示续当后的到期日。
- 上述本地验收针对 v19 基线；2026-09-11 经负责人试玩确认，授权推送并合并远端 main。发布整合基于 main 的 `3b72932`，保留新增夜客、四段灯光、职业赎当与寝屋功能。默认入口仍为 `scenes/start.tscn`，当前新局为 v21 夜市版；旧存档继续沿用原内容版本。不包含 Windows 新包或 Windows 实机验收。

## 玩家验收清单

1. 开新局完成首单：应仍需手动盖章；后续普通收购／活当应在不到一秒后自动继续。
2. 报一次低价、用一次不成立的理由、再成交：前两次不能出现收款或收货章；成交只扣一次钱。连点鼠标不能多扣款，也不能点穿到下一位客人。
3. 让排队客先超时：确认当前客人和交易页仍保留；只有排队者收到离场通知。
4. 连做两批不同买家的出货，再从账本打开第一批凭据：买家、件数、金额与当时现金前后值必须仍属第一批。
5. 分别检查只卖、只当、钱不够、轮次耗尽；确认意愿与临时不可用原因不混写。活当后查看期限，赎回后物品不再留铺。
6. 在自动演出中读取测试档或返回标题；重新进入不能重播旧交易。铜镜收购后必须继续出现存放规矩，夜间仍须处理必要选择。
